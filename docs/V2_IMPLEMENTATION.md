# 需求理解、画像确认与可信评测：第二轮实施记录

日期：2026-09-22。本文对应本地 v0.3 平台，替代上一轮“仅分析、未修改代码”的状态描述。工程验证、接口弱标、人工效果验证分别记录；没有人工标注就不填写人工 κ 或宣称模型已优于真人基线。

## 1. 本轮实现

| 上轮问题 | 当前实现 | 验证方式与边界 |
|---|---|---|
| 上传简历残留样例学历、年资与意向 | 页面默认不选样例；上传或改正文清空样例来源字段；保留用户明确设置的偏好并展示冲突 | 推荐、诊断、整理、面试和补证均要求当前画像确认令牌；令牌绑定会话、原文、偏好及解析版本 |

| AND/OR 被打平 | 保留岗位→要求组→子组→技能/任务的递归树，AND/OR执行三值逻辑 | 缺少证据为 unknown；OR满足一个完整分支即可；图预测不得创建事实 |

| 训练和线上特征不同 | 共用35维特征、查询模板、编码器、池化、截断、归一化与项目块聚合；保存固定检索回放 | BGE、Qwen及adapter区分模型合同；索引不匹配则明确回退；排序器默认只给影子分数 |
| 反馈没有改变推荐 | 可撤销的公司排除偏好；补证行动→明确保存单条证据→确认新增自述（未经外部核验）→显示版本差异→复测 | 已确认记录不可覆盖；过期记录不能复活；跳过不当负例；默认不存完整简历 |
| 人工标注无法进入可信训练 | 递归抽取盲审、任务hash、独立声明、原始评审导出、真实身份登记、显式仲裁、冻结CLI | 不同评审代号不等于不同真人；旧简化标签不能自动升级金标 |

实现入口主要是 `job_agent/{semantics,domain,profiles,retrieval_contract,ranking,workflow,journey,api}.py`、`research/{annotation_workflow,review_contracts,prepare_ranker,score_rankings}.py` 与 `web/platform/`。

最终完整CPU回归 **180项通过、1个依赖Torch的模块跳过**；该模块与模型、旧图/生成、向量模块在GPU环境合并运行 **37项及8个子测试通过**。新增用例覆盖补证并发、过期访问、缓存重载、429共享中止、断点与派生标签、来源失配拒绝训练和完整模拟流水线。模拟流水线包含17种方法的共同池比较与安全续跑，不代表真实教师实验已执行。前端JavaScript语法检查通过。上述为核心实现阶段记录；随后公开发布补充了7张实际浏览器截图、画像确认到算法比较的交互验收和390像素移动端检查，修复表单列溢出与导航换行，见[运行截图说明](SCREENSHOTS.md)。

最终复核修复了两类状态问题：确认补证时使用条件更新，绑定用户刚核对的那条原文，另一请求替换证据会使本次确认失败；过期研究事件、曝光与反馈在读取和授权时即被排除。向量缓存将内存元组与JSON列表规范为相同表示，避免每次重启重复编码全库。以上均有确定性回归，未改变r4解析器与训练数据划分。

本地Qwen3-4B指令服务已恢复，负责白名单补证行动选择与原经历块排序。两条虚构行动输入（含一条材料提示注入反例）均只返回允许的行动并绑定既有证据；另一次原段排序保持块多重集。它未作为本轮人岗教师，也未做新的生成模型微调；这些检查只证明约束路径可执行。

## 4. 接口标注与实验的实际状态

用户指定的接口配置只从仓库外 `.env` 读取，使用 `gpt-5.6-terra`，请求 `reasoning_effort=max`。模型返回名称已经实际核对；服务商没有公开底层revision，记录为 `provider-not-disclosed`。`max` 是请求参数，不是对第三方后台配置的独立认证。该参数的官方取值见 [模型说明](https://developers.openai.com/api/docs/models/gpt-5.6-terra)。

| 研究材料 | 规模/划分 |
|---|---|
| 明确合成画像 | 26份：14份通过先前自动检查的JD反推画像＋12份本轮独立撰写的虚构画像 |
| 画像分区 | 训练14、开发4、测试8；训练/评测用途分开，保留来源家族 |
| 固定共同候选池 | 493个人岗对，涉及478个岗位 |
| 需求片段 | 120条，来自训练/开发分区 |
| 真实人工评审与金标 | 0；κ、ICC及真人相关性收益保持未测 |

两个评审通道分别关注证据支持与任务迁移；第二通道反转批内顺序；有分歧或规则失败时再仲裁。相同模型的两个通道并不独立，不能把模型一致率叫双人人工一致率。

批量6条在本次第三方接口上出现超时，已改为2条微批，逐通道持久化、总墙钟限制和有限重试。任务、原文和标签版本不会因换执行顺序改变。发现模型可能把description中标题为“任职要求”的段落误称为requirements字段，引用必须定位真实JSON字段；仅存在逐字唯一命中的情况才允许有记录的字段纠正，其他情况继续模型复核。

后续接口持续返回HTTP429。单次诊断仍为限流，未提供`Retry-After`，不能据此推定欠费或账户余额不足。执行器已改为两队列共享限流门：首个真实调用通过后才放行并发，首次429关闭后续放行，保留正在完成的调用；缺恢复时间时等待300秒，默认并发1＋1，不无上限重启。工作台显示暂停状态与最早恢复时间。

当前保留98/493条人岗原始结果，按当前严格校验可用75条；其中17条仅字段位置错误，可逐字唯一定位纠正，派生后可用92条，余6条仍未通过。抽取保留38/120条，严格通过37条。派生纠正不改等级、理由、引用文字或原批次，且不因部分可用就冻结不完整候选池。

恢复训练时，会重新核验全部回放、冻结标签文件、r2→r4来源桥接、模型/代码/参数和阶段权重。来源改变须另建实验版本；不根据文件存在就复用旧LoRA或GNN。监督器分别检查493个人岗任务与120个抽取任务，全量抽取评测执行完成后才进入后续研究步骤；执行完成不等于抽取质量达标。

**完整493对标签尚未冻结前，不输出正式模型胜负表，不启动依赖完整标签的监督训练。** 实时状态及经过SHA校验的聚合进度见平台“研究工作台”；私有 `supervisor_status.json`、`annotation/manifest.json` 和实验 `progress.json` 保留精确阶段。接口超时、未通过引用校验和null等级不补成0，也不通过删困难样本完成评测。

### 需求抽取的进度分析

`research/evaluate_requirements.py` 对冻结片段单独做逐字定位、逻辑元数、递归、重复跨度及来源核验，再比较实体与要求组。一次固定进度快照中，120个预定任务已有38条接口结果，其中37条严格通过、1条逻辑元数非法、82条未完成。结果只用于定位问题，存在完成顺序偏差：

| 指标与分母 | 37条已通过样本的结果 |
|---|---:|
| 全部教师实体参照 | TP=19、FP=25、FN=119，micro F1=0.2088 |
| 93技能词典完整别名能覆盖的教师实体 | 19/138，13.77% |
| 仅词典内教师实体参照 | TP=19、FP=25、FN=0，micro F1=0.6032 |
| 叶集合一致且能唯一配对的逻辑组 | 仅1组，逻辑与模态均一致；不足以判断逻辑准确率 |
| 机器未知逻辑／模态 | 5/24组；12/48次提及 |

教师的`skills`包含专业、业务任务和组合能力，当前解析分支是技术技能词典，两者的类型与粒度并不完全一致。因此不能把开放F1称为人工技术技能准确率，也不能只选较高的词典内F1。该结果提示下一版需先明确“技能、任务、专业要求”的标签定义，再扩充抽取能力；本轮没有根据这37条改动冻结r4规则。部分样本通过不构成全量评测完成。

## 5. 可执行的模型路线

### 学习排序

固定回放包括BM25、dense、RRF、来源、标题与职类命中、技能与证据、任务对齐、学历/经验差、薪资IoU、区域、条件未知及要求组逻辑等35维。`salary_min`用于最低月薪硬过滤，`salary_max`参与期望区间IoU特征，并不自动把更高薪资当作冲突。

LambdaRank起点：200棵树、学习率0.04、15叶、深度5、每叶至少10样本、L2=1、开发集20轮早停、seed42。训练仅使用独立train/dev用途画像，显式排除测试画像家族。模型标签必须带 `--allow-model-labels`；模型默认为研究影子模式，不能自动替代规则推荐。

### 人岗向量微调

Qwen3-Embedding-0.6B，LoRA `r=16/alpha=32/dropout=0.05`，作用于q/k/v/o投影，学习率5e-5、温度0.05、实际查询batch2、每查询最多2个正例和2个核验难负例、3个epoch且最多30步。冻结基座与微调模型使用完全相同的简历与JD模板、512 token上限、最后有效token池化、L2归一化和0.6/0.4项目聚合。

grade≥2为正例；仅grade=0且明确 `hard_negative=true` 才是对比负例；未审对、grade1和未知关系均不进入负例分母。同批其他画像的正例不自动当负例。没有足够正负例的训练画像会明确列出，不能补造。

已完成的真实Qwen LoRA单步工程夹具验证可保存并独立重载，4,587,520个可训练参数，重载探针最大向量差0.0。**这是虚构工程验证，不能替代本轮493对教师数据上的训练结果。**

### 要求组GNN

使用冻结BGE节点文本初始化，岗位/AND/OR/未知组/技能/任务节点，带类型和不确定状态的消息聚合，简历自身文本归纳编码。模型不依靠测试标签连向正例，也不以找回同一完整JD为训练任务。

对照为显式逻辑、相同叶信息简单池化、真实要求组图和度数保持随机图；seed17/42/73，hidden32、AdamW学习率0.003、最多30epoch、开发集5轮耐心。池化对照的叶顺序规范化，避免浮点求和差异造成伪排名变化。随机图记录实际改变图数；没有可交换边的图不构成有效消融。

早期r2候选图的4,898条边中4,224条因解析作用域被标为unknown，不能称为可靠知识。r4图已单独重建：478岗位、26画像、540个512维冻结文本属性，5,402次属性读取无缺失；记录原r2任务、r4解析和编码器摘要。旧图没有被覆盖。

## 6. 评测解释与上线条件

主表只比较同一8份合成测试画像、同一已审共同池、同一硬条件过滤下的排序。BM25、BGE、融合、规则、LambdaRank、冻结/微调Qwen、显式逻辑及三种子图模型共用输入摘要。nDCG@10、池内Recall@10、MRR分别报告；按画像家族配对bootstrap，不把池内Recall叫全库召回。

BM25与字符TF-IDF索引在完整、无标签的岗位库上构建，模拟已知供给场景；画像与监督标签按家族隔离。该设置不等同于整条检索系统对完全未知岗位的归纳测试。组图模型的归纳参数与状态隔离另行验证，不能混用两个结论。

同时检查硬条件、逐字引用、引用对主张的支持、需求组逻辑、假实践、信息不足追问、整理事实保持、补证版本与可撤销偏好、公司多样性和延迟。API工程验收只证明对应规则生效；语义正确率和可读性改善仍需独立审核。

本轮允许模型教师弱监督试训，但教师相对增益不等于真实用户收益。人工身份未核实、标签未完整仲裁、共同池未冻结、硬违规增加或模型版本不一致时，不晋升模型。GNN如果没有稳定超过简单池化与随机图，保留研究结果，服务继续使用更简单的路径。
